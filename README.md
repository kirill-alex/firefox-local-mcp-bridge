# Firefox Local MCP Bridge

Локальный MCP-сервер и расширение Firefox для работы AI-агента с открытыми вкладками и текущими авторизациями. Поддерживает обычные WebExtension-действия и нативное управление через Firefox WebDriver BiDi.

**Статус: экспериментальная версия 0.1.0.** Windows — основная проверенная платформа. Это независимый проект, а не официальный продукт Mozilla или OpenAI. Полного совпадения с возможностями автоматизации Chrome не обещает.

## Возможности

- Вкладки, текст страниц, DOM-снимки, селекторы, iframe и скриншоты.
- Формы, клики, ввод, списки, checkbox, прокрутка и прикрепление файлов.
- Через BiDi: trusted-ввод, CSS hover, pointer drag/canvas, полный скриншот, консоль и сетевые события.
- Необязательное экспериментальное чтение подсказок установленного SyncShare на выбранных страницах Moodle. Подробнее: [SyncShare](docs/SYNCSHARE.md).
- Пауза, локальная авторизация случайным токеном и проверка источника HTTP-запросов.

Исходники сервера не требуют внешних библиотек во время работы. Для тестов используется jsdom.

## Требования

- Node.js 24 или новее.
- Firefox Desktop. Живые проверки проводились на Firefox 159.0.1 под Windows.
- MCP-клиент с поддержкой stdio; например Codex.

## Быстрый старт

Скачайте или клонируйте репозиторий, затем в его папке:

```powershell
node scripts/setup.mjs
```

Команда создаёт локальные `config.json` и `.local/pairing.html`. Токен генерируется для вашей установки и не выводится в консоль. Оба файла исключены из Git и архивов публикации. Повторный запуск сохраняет существующий токен.

### Подключить MCP-клиент

Для Codex с установленной CLI:

```powershell
node scripts/register-mcp.mjs
```

Это добавляет сервер `firefox-bridge` в пользовательские настройки Codex. Скрипт использует фактические абсолютные пути Node и текущего проекта. После регистрации откройте новый чат клиента, если список инструментов не обновился.

Для другого клиента задайте stdio-команду `node` с аргументом — абсолютным путём к `bridge.mjs`. Например:

```json
{
  "mcpServers": {
    "firefox-bridge": {
      "command": "node",
      "args": ["C:/Projects/firefox-local-mcp-bridge/bridge.mjs"]
    }
  }
}
```

Замените путь на свой. Если GUI-клиент не видит Node в PATH, укажите абсолютный путь к `node.exe` в `command`.

### Вариант A: обычное расширение

1. В Firefox откройте `about:debugging#/runtime/this-firefox`.
2. Нажмите **Load Temporary Add-on / Загрузить временное дополнение** и выберите `extension/manifest.json`.
3. В меню расширения откройте **Настройки**.
4. Откройте локальный `.local/pairing.html`, скопируйте токен и сохраните его в настройках расширения.
5. Запустите MCP-клиент. При отдельном запуске сервера: `npm start`.

Адрес моста в этой версии фиксирован: `127.0.0.1:17893`. Токен хранится в `browser.storage.local`. Он не включается в исходники или ZIP расширения.

Временное расширение удаляется при перезапуске Firefox. Постоянная установка в обычный Firefox требует подписи Mozilla; опубликованный здесь ZIP не подписан.

### Вариант B: WebDriver BiDi

Расширение для этого режима не требуется. Сохраните незавершённую работу и полностью закройте Firefox. Запустите:

```powershell
& 'C:\Program Files\Mozilla Firefox\firefox.exe' --remote-debugging-port 9222
```

Либо используйте `start-firefox-bidi.ps1`. Он не закрывает существующий Firefox и откажется запускать вторую копию поверх работающего процесса. Используется текущий профиль; восстановление вкладок зависит от настроек Firefox.

Попросите MCP-клиент вызвать `firefox_bidi_status`, затем `firefox_bidi_contexts`. Нативные инструменты используют строковые `contextId`, а расширение — числовые `tabId`.

## Как пользоваться

Примеры запросов агенту:

- «Покажи открытые вкладки Firefox».
- «Прочитай эту страницу и найди нужный раздел».
- «Заполни указанную форму и проверь значения полей».
- «Сделай скриншот тестовой страницы и проверь, сработало ли действие».

Перед действием агент должен изучить актуальный снимок страницы, а после — проверить результат. Ввод текста нужно прочитать обратно: в живой сессии наблюдалась потеря пробела, поэтому отправлять форму только по результату команды ввода ненадёжно. Отправка сообщений, форм и файлов должна соответствовать запросу пользователя.

## Ограничения

- Обычное расширение использует синтетические DOM-события; это не trusted input и не полноценная клавиатурная эмуляция.
- BiDi поддерживает настоящий ввод, но не гарантирует управление панелью браузера, всеми shortcut или системными диалогами.
- OS focus может не подтверждаться: отдельная `firefox_bidi_activate` возвращает `confirmed:false` через 1,5 секунды. Дальнейший ввод не блокируется.
- Прокрутка сообщает реальный результат `moved` и способ `mode`. В скрытом документе возможен DOM fallback. Для строгого native wheel задайте `mode:native`.
- Снимки DOM не являются нативным accessibility tree. Защищённые страницы Firefox, отдельные редакторы и закрытый Shadow DOM обычными инструментами могут быть недоступны.
- Расширение исключает приватные вкладки. **BiDi не наследует этот фильтр**: он работает с явно выбранными contextId.
- Консоль и сеть записываются только после явного включения мониторинга для контекста. Сетевые тела, cookies и заголовки в результат не включаются; URL и сообщения консоли всё равно могут содержать чувствительные данные.
- SyncShare — отдельное расширение и сервис. Проверено чтение его меню и состояния «Пока нет ответов»; успешное получение готовой подсказки из базы пока не подтверждено.

## Остановка

Пауза BiDi: `firefox_bidi_pause` с `{"paused":true}`. Уже запущенная команда может завершиться. Для остановки записи событий отдельно выключите `firefox_bidi_monitor` либо отключите сессию.

**Перед остановкой или обновлением сервера с активным BiDi вызовите:**

```powershell
node bridge.mjs --call firefox_bidi_disconnect
```

Firefox удерживает сессию после принудительного обрыва WebSocket. Если процесс был убит без `session.end`, может потребоваться полный перезапуск Firefox. Подробности: [BiDi](docs/BIDI.md).

## Разработка и сборка

```powershell
npm ci --ignore-scripts
npm run check
```

Проверка запускает тесты, сканирование публичных файлов и сборку неподписанного расширения в `dist/`. Тесты не подключаются к личному Firefox: используются моки, jsdom и локальный HTTP-сервер на свободном порту.

```powershell
node scripts/package-source.mjs
```

Исходный ZIP создаётся в `dist/` (сначала выполните `npm run build`). В него не попадают `node_modules`, `.git`, `config.json`, `.local`, старые файлы токенов расширения и артефакты сборки.

Не загружайте старый локальный комплект целиком: он мог содержать токен, личные пути и результаты реальных задач. Для публикации используйте эту очищенную папку или созданный ею исходный архив.
